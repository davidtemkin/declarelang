# Findings — 2026-08-04

## A1. A region read spelled `.value.<field>` is not reactive — RESOLVED

**What it looked like.** A `Dataset [ contents = { … } ]` reading another
dataset's region never recomputed when that region was written. Reported twice
independently — once here, once by eval run 2, which reinvented the tracker's
workaround from scratch without ever naming the bug.

**What it actually is, and it is not about derived Datasets.** Two spellings of
the same read, in the same attribute position, against the same write:

```
db.value.issues      →  "0"  "0"  "0"     never updates
db.read(["issues"])  →  "0"  "2"  "3"     correct
```

`db.value` hands back the raw parsed object, so `.issues` is plain JavaScript
property access — there is no cell to subscribe to, at any binding path. The
language's two sanctioned region reads (`:path` and `.read([…])`) go through
tracked accessors and are correct everywhere. `.value.<field>` is a third
spelling nobody sanctioned, and it silently yields a one-time read.

`bind.ts` names exactly the two supported forms:

```ts
const regionReactive = deps.some((rp) => rp.startsWith(":") || rp.includes(".read("));
```

**A candidate that looks right and is not.** Adding `.value.` to that predicate
moves the constraint to the tracking path, where it is *still* stale — tracking
has nothing to track either. The subscription is not missing; it is unobtainable
in that spelling. Two separate attempts were made on this before the isolation was
tight enough to rule it out.

**Complementary evidence.** `db.value = {…}` (whole-value assignment) DOES wake
such a constraint — `value` is a real slot. Only reaching *into* the tree fails.
That is why the corpus survives: a `DataSource` replaces its value on every fetch,
and a derived `Dataset` replaces its value on every recompute.

**Corpus exposure: zero live instances**, verified site by site. Of 30
`.value.<field>` reads: 26 are method bodies reached from handlers, where a
snapshot is the correct semantics; 3 are constraints over datasets that are only
ever value-replaced; 1 is a datapath whose cursor stays valid across the writes in
question, its fields updating through tracked `:path` reads. The single place the
trigger existed — a constraint reading `.value.<field>` on a *region-written*
dataset — was the tracker, and a clock stood in front of it.

**Still open: the diagnostic.** Nothing warns. The compiler already SEES the path
(`this.root.db.value.issues` appears in the wired deps), so it can refuse it in a
`{ }` value and name `:path` / `.read([…])` — the §A1-of-08-03 pattern: refuse what
cannot be wired, name the rewrite. The gating question is whether the refusal can
tell a constraint from a handler body, since it must not fire on the 26 correct
sites.

Two prose examples model the unsafe shape without being wrong in context
(`prose/DataSource.md:15`, `prose/Dataset.md:11`) — both read a value-replaced
source, so both work.

## A2. The tracker's `rev` clock — REMOVED

The clock threaded a mutation counter through nine method parameters, on the
stated grounds that *"a method's reads are not tracked — the ARGUMENTS are the
wiring"* (`tracker.declare`, and `declare.md` §5 says the opposite).

**The stated reason was false** — the compiler does read through method bodies,
measured. **The clock was nonetheless load-bearing**, which is what made this hard
to see: it was covering for §A1, one line deep, where `issuesOf` read
`db.value.issues`.

So the fix was one spelling:

```declare
issuesOf() -> array { return db.read(["issues"]) ?? [] },
```

With that, the projection tracks `db` itself, the clock is genuinely redundant,
and it and all nine threaded parameters are gone. 15/15 tracker tests, R1–R4 clean.

**The comments mattered more than the code.** Eval run 2 — a cold agent, one day
in — hit the contradiction between `declare.md` §5 and the tracker's comment,
picked the tracker's, and reinvented the clock. Its report says so explicitly:
*"had I followed §5 my projection would never have recomputed."* It was right for
the wrong reason. That is the corpus-endgame failure inside our own repo: the
flagship taught a defensive idiom, and it propagated on first contact. Every
comment teaching it is rewritten to say what is actually true.

**`groupRev` stays, and is now labelled as different in kind.** `_collapsed` is an
ordinary JS array on the instance, not a reactive slot, so nothing can notice it
change — that clock is doing real work. The honest fix is to make it a slot.

## B1. Tooltips were anchored to the unscrolled position — FIXED

`tip.ts publish()` summed ancestor x/y by hand. Measured: inside a pane scrolled
300px, a target SEEN at y=140 put its tooltip at y=309 — anchored to y=340, where
it would have been unscrolled. Now uses `rootFrameOrigin`, and it lands at y=187.

Third consumer to hand-roll that walk, after the Inspector's highlight (which is
why `rootFrameOrigin` was extracted) and `inspect()`. The shared function's comment
already warns against hand-accumulating; that has not been enough.

## B2. `apps/homepage/dist` did not record the platform it embeds — FIXED

The bundle is the runtime and the program in one file, and its `BUILD.json`
closure listed only `.declare` sources and assets — 21 entries, no runtime. So the
committed build could silently lag the repo. It was caught once, by luck: a runtime
change moved bundle sizes, which moved `stats.json`, which IS in the closure.

`writeBuildClosure` now records esbuild's own metafile inputs, so it cannot drift
from what was actually bundled: 76 entries, 55 runtime files. Verified by editing a
runtime file while holding its byte count constant, so `stats.json` could not move
— the gate fires directly now.

Note what was never broken: the browser side. `app.<hash>.js` is content-addressed
and `declare-boot.js` is `BUILD_ID`-keyed, so a visitor can never be served a stale
build. The gap was only in detecting whether the *committed* dist matched the repo.

**Still open:** nothing in the pre-commit chain rebuilds `apps/homepage/dist`. It
regenerates every other derived artifact; this one waits on someone remembering.
