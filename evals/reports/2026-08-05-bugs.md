# Declare — validated defects from the 2026-08-05 eval round

Found by cold agents building real applications from a brief; **every item below was
independently reproduced** at `2de9c3a` with the minimal case shown. Claims that failed
re-testing are listed at the end so nobody chases them.

Repro recipe for all of them:

```
node tools/verify.mjs <file>.declare [--assert <file>.assert.mjs]
```

---

## 1. `d.w` / `d.h` are documented, typechecked, and do not exist — HIGH

A drawing that sizes itself from the view's box silently draws **nothing**. No error at
any rung, no console warning, clean compile.

**Where.** `runtime/src/draw.ts` — `w`/`h` at lines 40–41 belong to `interface Bounds`,
not to the `Draw` class; `record()` (line ~419) does `new Draw()` with no box.
`docs/guide/06-style.md:93` promises the opposite: *"`d.w` / `d.h` are the view's own box."*

**Repro.**

```declare
App [ width = 300, height = 120, fill = white,
    a: View [ x = 10, y = 10, width = 120, height = 40,
        draw(d: Draw) { d.fillStyle = "#B4441E"; d.fillRect(0, 0, 100, 30) } ],
    b: View [ x = 10, y = 60, width = 120, height = 40,
        draw(d: Draw) { d.fillStyle = "#1F7A4D"; d.fillRect(0, 0, d.w - 20, 30) } ]
    ]
```

**Observed.** R1–R4 clean. The orange rect (literal width) paints; the green rect
(`d.w - 20`) paints nothing — `d.w` is `undefined`, the arithmetic is `NaN`, the recording
bounds to nothing and the canvas is removed.

**Expected.** Either the runtime supplies the box, or `d.w`/`d.h` are removed from the
scaffold so the reference to them fails to typecheck, and the guide sentence changes to
name `this.width` / `this.height`.

**Why it matters.** This is the one failure mode the language's pitch says is impossible —
a guessed name is a compile error, and here a *documented, type-checked* name is a silent
no-op. It cost the agent ~40 minutes and a three-view probe app to isolate.

## 2. `fetch()` after setting a URL dependency in the same handler requests the OLD address — HIGH

**Three independent sightings** across three agents and three applications, plus this repro.

**Where.** Constraint settle is a microtask; `DataSource.fetch()` reads `url`/`body`
synchronously. `DataSource.url`'s own reference entry says *"change a dependency … and the
**next** `fetch()` hits the new URL"*, which is exactly what does not happen from inside a
handler.

**Repro.**

```declare
App [ width = 300, height = 60,
    which: string = "halls",
    src: DataSource [ url = { `http://127.0.0.1:8310/api/${app.which}` } ],
    go() { which = "performances"; this.src.fetch() }
    ]
```

```js
// assert
export default async ({ page, drive, expect }) => {
  await page.evaluate(() => window.__declare.find("app").go());
  await drive.settleData();
  const r = await page.evaluate(() => ({
    url: window.__declare.explain("app.src", "url")?.value,
    requested: performance.getEntriesByType("resource").map(e => e.name).filter(n => /api/.test(n)),
  }));
  expect.fail(JSON.stringify(r));
};
```

**Observed.**

```
url after settle:   …/api/performances
ACTUALLY REQUESTED: ["…/api/halls"]
```

**Expected.** `fetch()` flushes pending writes before reading `url`/`body` — or the
documentation states the hazard plainly and names the supported shape.

**Real-world shapes it broke.** A route-derived seat map (stale data); a
`DELETE /api/sessions/` sent with no id.

## 3. `input(v)` on a `TextInput` compiles clean and never fires — HIGH

A silently dead field that saves `null` forever.

**Where.** `TextInput` is an `Editor` and delivers through the **event** `onInput(v)`
(`runtime/src/text-input.ts` fires `"input"`, which resolves to `onInput`). Guide ch. 8 and
`declare.md` §11 teach `value = { … }` + `input(v)` as *the* value pattern — correct for
`Checkbox`, `Slider`, `Segmented`, wrong for editors, and nothing says which family a
component belongs to.

**Repro.**

```declare
App [ width = 320, height = 90,
    who: string = "",
    f: TextInput [ width = 200, height = 30, fontSize = 16,
        text = { app.who }, input(v: string) { app.who = v } ],
    Text [ y = 45, text = { `who=[${who}]` } ]
    ]
```

**Observed.** After typing `Ada`: `app.who = ""`, `field.text = ""`. Nothing at any rung.
Writing `onInput(v: string)` instead works correctly.

**Expected.** A warning (or error) when an `input` member is declared on an `Editor`
subclass — this is a dead member, and the language otherwise makes that class of bug
unrepresentable. Plus one line in the value-pattern docs distinguishing **controls**
(`input(v)` method) from **editors** (`onInput(v)` event).

## 4. A `:path` inside a `Spring` or `State` leaks an internal slot name — MEDIUM (diagnostic)

**Repro.**

```declare
class Row extends View [ height = 12,
    hot: State [ applied = { :on }, opacity = 0.4 ]
    ]
App [ width = 200, height = 60,
    d: Dataset { { "rows": [ { "on": true } ] } },
    box: View [ datapath = { app.d.value }, Row [ datapath = :rows[] ] ]
    ]
```

**Observed.**

```
'$data' is not a member of State — declare it ($data: <type> = …) or fix the name [DECLARE6001]
```

The same message appears for `Spring [ to = { :mins / 60 } ]` with `Spring` in place of
`State`. Following the advice literally — declaring `$data` on a `State` — is nonsense.

**Expected.** *"A `:path` resolves against a view's datapath; a `State` has none — read it
into an attribute on the enclosing view and point `applied` at that."* Likely shared by
`Animator`.

## 5. `explain()` is silent on layout-owned geometry — MEDIUM

**Repro.** Any child placed by a `SimpleLayout`:

```js
window.__declare.explain("app.0.g2", "x")
→ {"attr":"x","value":20,"set":false,
   "constraint":{"label":"View.x","static":false,"live":false,
                 "deps":null,"source":null,"pos":null},"spring":null}
```

**Expected.** Name the writer: *"written by `SimpleLayout` on `<parent path>`"*.

**Why it matters.** `explain()` is the most-praised affordance in the language and the tool
agents reach for when geometry is wrong — which is precisely when the answer is "a layout
wrote it". One agent lost its longest debugging stretch here.

## 6. `Heartbeat.onFrame(dt)` delivers a negative `dt` across a clock handover — MEDIUM

**Not independently reproduced** — reported with specifics and included because the
mechanism is concrete and it affects every app driven at rung 5.

Under `verify`'s `settleMotion` (which calls `__declare.clock.manual()`), the previous
timestamp is a `performance.now()` value while the manual scheduler starts near zero, so
the first frame's `dt` was **−0.72 s** and an integrated fling ran backwards. The docs say
`dt` is clamped so a backgrounded tab does not resume with one enormous step — which reads
as a promise that `dt` is sane; it is clamped at the top only.

**Expected.** Clamp at both ends, or reset the previous timestamp on a clock-mode change.

## 7. Documentation — small, confirmed

- **The "no type annotations in bodies" rule is stated too narrowly.** `declare.md` §2
  glosses it as being about attributes. It also bans local `const`/`let` annotations and
  lambda parameter annotations in every method and value body — while `script { }` accepts
  full TypeScript, so the identical syntax is legal three lines up and illegal three lines
  down. Confirmed: `script { function f(n: number): number[] }` compiles;
  `const xs: number[] = …` in a method body is `DECLARE2000`.
  *Suggested clause:* "including local bindings and lambda parameters; narrow with `x as T`."

- **A `script` constant cannot be used in a bare value slot.** `tint: Color = SEAT_FREE`
  is refused ("not a CSS color name") while the same constant works inside any `{ }`.
  The diagnostic is clear; the asymmetry is stated nowhere.

- **The value-slot table omits bare array slots.** `listenTo = ["a","b"]` compiles, as does
  the braced form. §2 documents three forms; this is a fourth.

## Checked and NOT defects — do not chase

- **"An unfilled full-frame `View` silently absorbs clicks."** Documented behaviour:
  `declare.md` §8 — every view takes presses unless `visible = false` or
  `pointerEvents = "none"`, and a transparent view is "the natural press-catcher".
  Declaration order is z-order. The app declared an empty container in front of its content.

- **"A primary button cannot be activated by synthetic input."** `drive.click` activates it
  correctly; the failure was the eval harness's own coordinate arithmetic.

- **"An auto-sizing view inside a `SimpleLayout` produces `x: NaN`."** Did **not** reproduce
  minimally, with or without `width = { contentWidth }`. Reported as costing ~40% of one
  run, so the failing structure is real but has not been isolated — needs the original
  before any fix is attempted.
