# rows that write their records, lists that keep their place, and an agent's front door

Records stay where they live: a list derived from a dataset shows the source's own records,
so a row bound to it edits the real thing, and each record can be built as the class it is.
Long lists keep the reader's place through every kind of change, on every renderer, and a new
conformance probe holds the virtualized list to the fully built one. And the documentation
for agents is reorganized around reading only what a task needs.

## A derived list holds its source's records

A `Dataset` that selects from another — filter, sort, group — now holds the source's own
records rather than copies, so a row bound to it writes `:field = v` straight into the source.
What a derivation *made* (a summary, a computed record) is read-only, and a write to it is
refused with the reason. To add a field computed across records, wrap the record instead of
copying it:

```declare-fragment
cal: Dataset [ contents = { app.buildModel() } ]
```

where `buildModel()` returns `{ ev: e, lane: n }` for each event: a row bound through `:ev`
edits the source event.

A replicated view knows its place: **`rowIndex`** is its record's index in the array, a fact,
so records carry no position fields. And records of different kinds are different classes:

```declare-fragment
classFor = { :kind == "heading" ? Heading : Item }
```

on the replicated view builds each record as its own class; what state a row is *in* stays a
`State`. A class with no `extends` is a view; any other base is named (`extends Node`,
`extends Dataset`, `extends Control`).

## Long lists keep their place

`virtualize = true` builds only the rows near the viewport, and a reader now sees the same
list a fully built one would show, record for record, through insertions above the reader,
rows that grow or spring open, removals, a filtered or reversed list, a narrower column, a
container or window that changes size, and fast flings. A reader at the end stays exactly at
the end as rows there measure. Views stacked after the rows (a "loading more…" line, a footer)
sit after the last row. A row parked for reuse presents no record: its `rowIndex` is −1, and a
`TableRow`'s `tableIndex()` is −1, so a table's keyboard walk never lands on one.

Keeping the reader's place is sharper in fully built lists too: a correction no longer counts
as the reader scrolling, and when the top edge runs through a row's bottom padding, the row
below is the one held still.

## Pointer events carry both frames

Every pointer event carries `x`/`y` in the view's own frame, `rootX`/`rootY` in the app's —
the frame a drag reads, because it does not move with the dragged thing — and
`deltaX`/`deltaY` since the press, on the DOM, canvas and the Mac.

## A class with no view starts its members

A `Node` subclass — a model, a service — starts what it holds the way a view does: a `Time`
ticks, a `Socket` connects, an animator runs, a `State` applies, and a derived `Dataset` inside
it derives and drives replication. `Text` honours `padding` on every renderer, and a `{ }` that
yields null before its data arrives draws an empty run.

## Smaller changes

- The checker now refuses four programs that used to fail only at boot: a `Spring` on an
  attribute its view binds (`DECLARE2005`), a member named like one of the runtime's own, a
  class or schema named like a TypeScript standard type (`DECLARE4015`), and a `datapath`
  whose `{ }` is a literal no `Dataset` holds (`DECLARE3006`). Each names the form that works.
- A `Control`'s default `onClick` is `press()`; override `press()`, not the handlers.
- A Markdown or `HTMLText` document on the DOM is one native flow of real elements; links are
  underlined by default (`linkUnderline`); a clamped `Text` copies its whole run.
- For agents: `skill/SKILL.md` is the front door — read `docs/declare.md`, then write, and look
  everything else up when it is needed. `npx declare-help briefs` lists the task briefs and
  `npx declare-help brief <name>` gives one; `declare-help --example` shows a name in the
  guide's compiled code.
