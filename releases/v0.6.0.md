# one way to edit a value, for every control

Every control that holds a value — a checkbox, a slider, a date, a text field, and any of
your own — now edits it the same way, and says so in the same words. The person changes what
the control shows; `admit` may refuse or tidy the change before it appears; `commit` puts it
into your state. While they are editing, the control shows what they are doing, whatever your
value does meanwhile, and when they stop it shows your value again. `<->` is the shorthand for
the common case, on any control. This release changes how programs are written, so it comes
with a way to move them over: its "Changes to make", below, and `npx declare-changes`.

## `commit`: where a change goes

A control shows your value and hands the person's change to `commit`:

```declare-fragment
Checkbox [ label = "Mute", checked = { app.muted }, commit(v: boolean) { app.muted = v } ]
```

When the change goes straight back to where the value came from, say it once — on any
control, to a record's field or to an attribute:

```declare-fragment
Checkbox [ label = "Mute", checked <-> app.muted ],
TextInput [ accessibilityLabel = "Title", value <-> :title ],
Slider [ accessibilityLabel = "Volume", value <-> app.volume ]
```

## What the person is doing stays on screen

A typed "4" in a size field whose `commit` clamps to 8 still shows "4", so "48" can be typed; a
slider whose `commit` rounds still follows the finger. When the person leaves the field,
releases the thumb or presses Return, the control shows your value. A change to your value from
anywhere else — a Reset button, a service — ends the edit and shows at once. `commitOn = "end"`
commits once, when the edit ends, and Escape then cancels it.

## `admit`: refuse or tidy a change before it appears

```declare-fragment
TextInput [ accessibilityLabel = "Font size", value = { String(app.size) },
    admit(t: string) -> string | null { return /^[0-9]{0,3}$/.test(t) ? t : null },
    commit(t: string) { if (t != "") app.size = Math.max(8, Math.min(400, Number(t))) } ]
```

A letter never appears, nor a fourth digit, and the platform's Undo still works: a refused
change never entered it, and a tidied one is one step. This holds in Chrome, Safari and
Firefox, in canvas mode, and in native fields on the Mac, where the field asks the program
before AppKit applies the change.

## A field is a value control

`TextInput` is now written in Declare, in `library/textinput.declare`, as a `ValueControl` over
`NativeText` — the runtime's native editable text, which you can put in a view of your own to
make a field of your own. Its value is `value`; `text` is what is on screen, read-only. Every
library control with a value is a field for a `Form`: `name`, `required`, `validate`, a
service's refusal, judged when the person leaves it.

## Saying which release a program was written for

`npx declare-changes app.declare` lists what changed since the release a program was written
for, and where in the program each change applies — the before and after, the docs to read,
and the changes that make no error. When a migration is done and `declare-verify` is clean,
`npx declare-changes --done app.declare` writes the program's first line,
`declareVersion [ "0.6.0" ]`, so the next release's list starts from here. No program needs
the line.

## Changes to make

### `onInput` → `commit`
A text field hands the person's change to `commit`, as every value control does.

Find: `/\bonInput\s*\(/`

```declare-fragment
TextInput [ accessibilityLabel = "Name", text = { app.name }, onInput(v: string) { app.name = v } ]
```

```declare-fragment
TextInput [ accessibilityLabel = "Name", value <-> app.name ]
```

Docs: [Controls](declare-docs:guide:controls@the-value-pattern) · [`ValueControl.commit`](declare-docs:ValueControl.method.commit)

Watch for: an `onInput` that only watched a field which kept its own text. As a `commit` it replaces the field's own, and the field forgets what was typed when the person leaves it — write `value = t` in it too, or bind the field with `value <-> …`.

### `input(v)` → `commit(v)` on a control with a value
`Checkbox`, `Switch`, `RadioGroup`, `Slider`, `Stepper`, `Combobox`, `DatePicker` and `MonthCalendar` deliver through `commit`.

Find: `/\b(Checkbox|Switch|RadioGroup|Slider|Stepper|Combobox|DatePicker|MonthCalendar|SearchField|TextInput)\s*\[(?:[^\[\]]|\[(?:[^\[\]]|\[[^\[\]]*\])*\])*?\binput\s*\(/`

```declare-fragment
Checkbox [ label = "Mute", checked = { app.muted }, input(v: boolean) { app.muted = v } ]
```

```declare-fragment
Checkbox [ label = "Mute", checked <-> app.muted ]
```

Docs: [Controls](declare-docs:guide:controls@the-value-pattern) · [`ValueControl`](declare-docs:ValueControl)

Watch for: `Segmented`, `TabBar`, `Tree`, `Window`, `Sheet`, `Disclosure`, `Splitter`, `ToolButton`, `AppearanceSwitch` and `TextSizeSwitch` keep `input(v)` — they are not value controls. A value control of your own extends `ValueControl` and calls `edit(v)` where it called `input(v)`. A `commit` override on a control whose value is not constrained replaces the control's own and leaves it unable to change.

### A field's `text` → `value`
A field's value is `value`; `text` is the text on screen, read-only.

Find: `/\b(TextInput|SearchField)\s*\[(?:[^\[\]]|\[(?:[^\[\]]|\[[^\[\]]*\])*\])*?\btext\s*(=[^=]|<->)/`

```declare-fragment
TextInput [ accessibilityLabel = "Title", text <-> :title ]
```

```declare-fragment
TextInput [ accessibilityLabel = "Title", value <-> :title ]
```

Docs: [Data](declare-docs:guide:data@editing-text-and-forms) · [`TextInput.value`](declare-docs:TextInput.value)

Watch for: `<->` no longer converts: a field bound to a `number` field is a type error — show it converted, `value = { String(:qty) }`, with a `commit` that parses. It no longer holds back a value `validate` rejects: every change is committed, and `validate` only judges — keep invalid text out of the data in your `commit`. A field chosen by name is `value <-> { :@[(classroot.field)] }`. A write to `field.text` is a compile error: write `field.value`.

### `initial` → `value` with a `commit` that keeps the text
A field seeded from a value, then the person's, is the value pattern with nothing new.

Find: `/\binitial\s*=[^=>]/`

```declare-fragment
TextInput [ accessibilityLabel = "Address", initial = { classroot.slug } ]
```

```declare-fragment
TextInput [ accessibilityLabel = "Address", value <-> classroot.slug ]
```

Docs: [Data](declare-docs:guide:data@a-form-in-a-sheet)

Watch for: with nothing of yours to write, `value = { source }` with `commit(t: string) { value = t }` follows the source until the person types, then keeps their text.

### `commitOn` → `"each"` or `"end"`
When `commit` is called: after each change, or once when the edit ends.

Find: `/commitOn\s*=\s*"(input|blur|enter|manual)"/`

```declare-fragment
TextInput [ accessibilityLabel = "Title", commitOn = "blur", text <-> :title ]
```

```declare-fragment
TextInput [ accessibilityLabel = "Title", commitOn = "end", value <-> :title ]
```

Docs: [`ValueControl.commitOn`](declare-docs:ValueControl.commitOn)

Watch for: `"input"` is `"each"`; `"blur"`, `"enter"` and `"manual"` are `"end"` — the edit ends when the person leaves, presses Return, or your code calls `endEdit()`.

### The edit session's verbs → `endEdit`, `cancelEdit`, `editing`
A field's draft is the edit every value control has.

Find: `/\.revert\s*\(\s*\)|\.dirty\b/`

```declare-fragment
Button [ label = "Cancel", onClick() { app.title.revert() } ]
```

```declare-fragment
Button [ label = "Cancel", onClick() { app.title.cancelEdit() } ]
```

Docs: [`ValueControl.endEdit`](declare-docs:ValueControl.method.endEdit) · [`ValueControl.cancelEdit`](declare-docs:ValueControl.method.cancelEdit)

Watch for: a field's `commit()` with no argument, from a Save button, is `endEdit()`; `dirty` is `editing`.
