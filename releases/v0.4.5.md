# provided values, fonts as objects, and a view inside a sentence

The longest stretch between releases so far, and it reshapes three things an author
touches constantly: how a look reaches a subtree, how a program names a typeface, and
what a run of prose may contain. Scrolling became facts, drawing grew a real
vocabulary, and every built-in is now a class you can extend.

## A look reaches down by being provided

`provided(name, default)` reads the nearest value an ancestor provides — the mechanism
behind `fontSize`, `textColor` and the theme, now sayable directly. A theme is a
top-level declaration, and an app provides one:

```declare-fragment
theme Brand [ accent = #4C8DFF, surface = #0B141B ]

App [ theme = { { ...SanFrancisco, accent: Brand.accent } },
    Text [ textColor = { provided("theme").accent }, text = "follows the app" ]
    ]
```

The rule is one sentence: **a value set locally always outranks a provided one.** A
`Text` that sets its own `fontSize` ignores the region's; a provided value is a default
a node overrides, never a rule that fights your code. The old `stylesheet` and the
per-view `styles` list are retired — a look shared across whole views is a subclass, a
look worn by a run of prose is a `style` bundle, and a look that follows its
surroundings is provided.

## A typeface is an object

The `font` declaration is gone. A `Font` is a node with `Face` children, so a family
and its weights are ordinary members, and loading is ordinary reactive state:

```declare-fragment
App [ body: Font [ family = "Inter", Face [ weight = 400, source = "inter.woff2" ] ],
    fontFamily = { app.body },
    Text [ text = "set once, provided down" ]
    ]
```

Measuring came with it. `measureText(text, style, width?)` answers with a style you
name rather than a hidden ambient one, and **`providedTextStyle(overrides?)`** hands
you the five provided face values as a `TextStyle` — so measuring the face in force
where you are standing is one call, in a view or inside `draw()`.

## Drawing, and painting text

`draw()` is an ordinary method a constraint calls — never a special shape — and its
vocabulary is now wide: filters and masks, `radialGradient` and `conicGradient`,
`frost`, per-corner `cornerRadius`, image fitting with `stretches` and `alignX`/`alignY`,
affine and 3D transforms, `drawImage`, and styled runs through `fillText`/`strokeText`
taking the same `style` bundle a `<span class>` wears. Every one of them renders on all
three renderers — DOM, canvas, and the native Mac host.

The cost is charged to the program that asks: whole modules ride only when a program
names what they serve, so an app that draws no filters carries no filter code.

## Scrolling is facts and requests

A scroll position is a fact you read (`scrollY`, `scrollX`, `scrolling`,
`scrollStartY`), and moving one is a request you make (`scrollTo`) — never a value you
assign and hope. The canvas renderer runs its own scroll loop and the Mac host scrolls
host-side, so the three targets agree about momentum, rubber-banding and where a view
is *seen*.

## A view inside a sentence

Rich text now takes your own view classes. A self-closing tag naming one of them is a
real view, flowed in the line as a box the words wrap around:

```declare-fragment
class Chip extends View [ label: string = "",
    height = 19, width = { this.t.width + 18 }, cornerRadius = 9, fill = #DDF4E4,
    t: TextLabel [ x = 9, fontSize = 11.5, text = { classroot.label } ] ]

HTMLText [ html = "Filed under <Chip label='docs'/> this morning." ]
```

Nothing declares the capability — the class existing is what makes the tag mean it. The
tag's attributes are the class's, converted from their strings by each slot's declared
type, and the tag is the **use site**, so it outranks the class body exactly as an
instance literal does. The view owns its size, the flow owns its position, it sits on
the first baseline inside it, keeps its own state when the content changes, and re-flows
the line when it resizes. `<span class>` stays a style and is never a view;
`escapeHtml` is there for content you build from data.

## Every built-in is a class you can extend

`Spring`, `Animator`, `AnimatorGroup`, `Dataset`, `DataSource`, `Keys`, `Focus`, `Tip`,
`State`, `EventStream` and `Socket` join `View`, `Layout` and `Node`: one class chain
serves every family, and only an abstract family refuses. A subclass may also replace a
built-in's own runtime method and call it:

```declare-fragment
class Feed extends DataSource [ fetch() { app.tries = app.tries + 1; super.fetch() } ]
```

## Prose, and the change event

`Markdown` is a CommonMark parser now — tables, nested lists, reference links — with
`maxLines`/`truncated` over a whole document and `richTextLayout` for a per-block
measure. And a view that must act when a value changes declares it:
`trackChanges = ["height"]` plus `onChange(e: ChangeEvent)`, with the previous and
current values on the event.

## Also

- `key = :field` names a replicated row's identity; `:path` reads the nearest view's
  cursor from any member.
- `WrappingLayout` gained `indent`, `hangingIndent` and `justify`; `align` works on
  both layouts and a baseline can be claimed.
- `activeTone(accent, surface)` replaces `tint` — the tinted step a control wears while
  it is on.
- `Combobox` and `DataGrid` floor their menus with `minWidth`; `Menu`'s check column
  follows checkability.
- Two new warnings: overriding runtime plumbing, and a class name that shadows a
  rich-text tag.
