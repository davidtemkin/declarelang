# headers, unions, coded errors

Most of this release was driven by a field report: the first non-trivial
Declare app built against a real external API (a GraphQL endpoint behind an
API key and a sign-in), 837 lines against ~48,000 for the matched slice of
the React app it mirrors. Every finding was reproduced before it was fixed.

## `DataSource` carries headers

A real API wants a header — an API key, a bearer token — and that is now an
ordinary attribute. It is a record, merged over the `Content-Type` a JSON
`body` sets for itself, and **reactive like any other slot**:

```declare-fragment
api: DataSource [ url = "/graphql", method = "POST", auto = true,
    headers = { ({ "x-api-key": app.key,
                   Authorization: app.token != "" ? "Bearer " + app.token : "" }) },
    body = { ({ query: app.query }) } ]
```

A header whose value is empty is **not sent**, so that ternary is the whole
"only when signed in" story — no branch, no second source. When the token
lands the header re-derives, and with `auto` the request follows. Before this
the declarative primitive could not reach an authenticated endpoint at all;
the report's app fell back to hand-written `fetch()` for every call.

## A literal union is a type, everywhere

`"idle" | "loading" | "done"` was sayable as a schema field and refused on an
ordinary declaration — the same closed set stateable about *data* and not
about the state derived from it. It is now a type in every position:

```declare-fragment
class Fetcher extends View [
    phase: "idle" | "loading" | "done" = "idle",
    advance(to: "loading" | "done") -> "loading" | "done" { this.phase = to; return to },
    ]
```

The members are enforced at both ends — a bad default is refused at the
declaration, a bad assignment by the typechecker (`Type '"wat"' is not
assignable to type '"idle" | "loading" | "done"'`).

**One rule settles how a member is spelled: as its declaration spells it.**
`Axis` declares `y`, so `axis = y` and never `"y"`. A literal union declares
`"idle"`, so `phase = "idle"` — in a slot exactly as in a `{ }` — and the
bare token is refused with the quoted spelling named. (Number unions,
`col: 0 | 1 | 2`, remain a schema-field type for now.)

The same rule reached two built-ins that had been plain strings:
`DataSource.method` and `.format` are closed sets now — `method = "PATCHE"`
is refused at compile, in a slot and in a body, where it used to fail at the
fetch. Spelled as they always were.

## Production builds ship error codes, not error prose

A shipped app carried every error sentence it could throw as a string
literal. A production build now codes them:

```
[Declare E3A14CE] /nope/deep, '/nope' is missing
```

The throw, the position, and every value the message interpolated survive —
only the sentence goes — and `declare-help E3A14CE` gives it back, with the
file and line it is thrown from. A code is derived from the message itself, so
it is stable until the message is reworded. **Development is untouched**: the
dev server, the live-compile pages, every test, and `declarec --debug` keep
the full sentences, because that is where you meet these errors. Text an app
renders (a `DataSource`'s `.error`) is never coded. The flagship calendar
goes 86.1 → <!--stat:calendar.wireKB1-->85.0<!--/stat--> KB gzipped, measured
at this tag.

## Script blocks share one scope

Several `script { }` blocks always *compiled* as one namespace and now
*evaluate* as one: a block-2 function calling block-1's works, where it used
to throw at the first call. Along the way, the two forms are told apart
plainly — `script { "helpers.ts" }` (a block whose whole body is a string,
evaluating to nothing) is refused with the `script [ "helpers.ts" ]` rewrite
named. `import` works everywhere on the Node toolchain, files and inline
blocks alike; `export` is optional in a file and refused inline.

## The silently invisible app — DECLARE4008

`shows = "home"` is not a label; it lowers to the view's visibility. With
`location = ""` the report's app rendered `display:none` forever, and every
screen's own `visible` was evaluating correctly the whole time. When no
`shows` name matches the program's literal initial `location` and no ungated
view sits at the root, the compiler now says so and lists the locations that
would work.

## Call-site type arguments are stripped

`gqlRequest<{ items: Track[] }>("q")` passed every static rung and then died
in the browser: `<` parsed as less-than and the type's names evaluated as
variables. The stripper handled `as T`, `<T>x` and `x!`; it now handles
`f<T>(…)` and `new C<T>(…)`, nested generics included.

## A layout and a slot its child owns

A `place()` returning a slot the child had bound (`width = { … }`) threw
mid-settle and, on a reactive rearm, re-fired every wave — hundreds of
uncontained throws that half-broke an app. The one-owner rule now resolves it
in the author's favour: the layout leaves that slot alone, arranges the rest,
and reports it once, in one wording at every site that can meet it — naming
the layout, the slot, whether it sizes or positions, and the way out
(`ignoreLayout = true`).

## A tenant that loads itself

The embedding chapter gains the pattern a heavy foreign dependency wants: a
`DOMIsland` declaring an `external` fact, a small loader in the slot that
`observe`s it and fetches the SDK when the fact turns true. Nothing in the
program names the dependency, so nothing in the build can bundle it. One
caveat is documented beside it: in a `script`, `import()` of a URL stays
external and truly defers; a bare package specifier is resolved and bundled
whole.

  in a synthetic backend; drive it with `--assert` or the dev server.
