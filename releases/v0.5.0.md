# a guide that re-teaches the language, packages that declare what they carry, and buttons that answer the pointer

The guide is rewritten from the first page: thirty chapters, in the order a program is
actually built — core concepts, the notation, constraints, running and checking; then
components, layout, data, collections, motion, addresses, renderers, embedding and
packaging; a full reading of the calendar; and an appendix with a glossary and a
phrasebook for readers coming from React, CSS or SwiftUI. Every chapter's examples are
live and editable, every code object links to its reference page, and the first chapter
ends with a map of the shipped applications — which one to read for each topic, and
what in it to look at. That rework is why this is 0.5.

## A package is one file, and it carries what your program declares

`npx declarec` builds a folder that needs nothing outside itself: an `index.html`, one
`app.<hash>.js` holding the runtime, your program with every `{ }` body already a
function, and only the components it can construct — and your program's own folder,
swept in. No host parses anything: the dev server, the static site and a package all
boot the same built program.

What a build cannot read from a literal, the program states in a top-level `ship` block:

```declare-fragment
ship [
    islands = ["../calendar/calendar", "../birds/birds"],   // mounted by a computed program
    files = ["desktop.declare"]                             // read, but named by no literal
]
```

`compiler = true` carries the compiler for a program that compiles source while it
runs; `inspector = true` carries the Inspector. A component can carry its own block, and
the program's is the union. The *Packaging* chapter has the whole account.

## What a layout places belongs to the layout

A row places each child's `x`, and with `align` its `y` too. A child the layout places
may no longer also set that attribute — as a number, `center`, or a `{ }` — and doing so
is a compile error at that line, naming what to use instead. One attribute, one owner.
A child that must stand apart says `ignoreLayout = true`.

## The outside world arrives as members

A `{ }` body reaches the world through members of the tree — a `DataSource` for a
request, a `Time` for a repeating call — and through one helper for a single later call:

```declare-fragment
onInput(v: string) { app.query = v
    afterDelay(300, () => { if (app.query == v) app.searched = v }) }
```

A `Time`'s `tick` may now be a number of milliseconds (`tick = 30000`). A body that
names `fetch`, the timers or `globalThis` is refused, with the member to use named;
host APIs the language does not cover belong in a `script` block, whose scope is the
program's own.

## Two new path forms

`:@` names the record under the cursor itself — a string in a list of tags, or the
whole object a row presents. `[( … )]` is a key computed by TypeScript, anywhere in a
path, readable and writable:

```declare-fragment
Text [ datapath = :tags[], text = :@ ],
TextInput [ text = { "" + :@[(classroot.field)] },
    onInput(v: string) { :@[(classroot.field)] = v } ]
```

## Primary buttons answer the pointer

A primary `Button` now climbs the same state ladder as a secondary one, in the accent:
`accentHover` under the pointer, `accentPressed` while held or while its menu is open.
Each preset follows its platform: San Francisco steps darker in light and lighter in
dark; Mountain View uses Material's state layers; Redmond uses Fluent's accent fills; and
Cupertino, like a Mac, has no hover on any control — pressing darkens in light and
lightens in dark. **A theme record that
does not spread a preset must now state `accentHover` and `accentPressed`.**
