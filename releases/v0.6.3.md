# a layout belongs to the element it is written on

One rule, said plainly and now kept everywhere: an object has one set of children, arranged by
one layout. A `layout:` is the layout of the element it is written on, whether a class, a
subclass or a use site writes it. `defaultPlacement` moves children into a class's content
view, and only children; that view arranges them with its own layout. Since 0.6.0, a layout
written beside placed children moved into the content view instead, and a frame with a
layout of its own was left with none. That is the one breaking change. The rest are fixes.

## Breaking changes

### `layout:` beside placed children → a View with that layout around them
A `layout:` arranges the element it is written on; content a class places is arranged by the view it is placed in.

```declare-fragment
Popover [ layout: SimpleLayout [ axis = x, spacing = 8 ],
    Text [ text = "One" ], Text [ text = "Two" ] ]
```

```declare-fragment
Popover [
    View [ layout: SimpleLayout [ axis = x, spacing = 8 ],
        Text [ text = "One" ], Text [ text = "Two" ] ] ]
```

Docs: [`View.defaultPlacement`](declare-docs:View.defaultPlacement) · [`View.layout`](declare-docs:View.layout)

Watch for: a subclass of a class that names a `defaultPlacement` (a `Sheet`, a `Dialog`, a frame of your own) and writes `layout:` to arrange the children it adds. That layout now arranges the frame itself. Where the frame's own children state positions, boot says so ("the layout written on the … is …'s own"); where they don't, the frame rearranges without an error.

## Smaller changes

- **A form sends once.** A second `submit()` before the first has sent (two in one turn) does
  nothing, as one while `pending` does. Both used to reach `send()`, so a form with a service
  posted twice. The `Form` reference also says what `super` does in `refusal()` and
  `refusedWith()`.
- **A combobox keeps the focus.** A row picked with the mouse left the focus on nothing, so the
  next Tab started from the top. The focus stays in the field.
- **`declare-look --wait-real MS`** lets the program run live for real time, for what arrives on
  the world's clock (a socket's or a service's timed messages). `--wait` says it is the
  program's own time, which is held between steps.
- Docs: `app.keyboardHeight` beside the bar at the window's foot (Scrolling); a sign-in whose
  fields say their `purpose`, in a `Form` that sends through a `DataSource`, is offered for
  saving by the browser's password manager (Accessibility).
