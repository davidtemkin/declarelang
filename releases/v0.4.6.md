# a kernel for the reactive core, and a boundary that says its own direction

The reactive core — the graph, the queues, the settle, the visibility walk, layout,
text sizing, springs — moved out of JavaScript into one C11 source that runs the same
way on every host: compiled to WebAssembly in a browser, linked directly into the Mac
app. Nothing about how you write a program changed; what changed is how much of it now
runs as bytecode the kernel evaluates itself, without a round trip back into JS.

Measured against the previous release, on one corpus of real interactions, across four
JavaScript engines and three operating systems: settle time — the whole reactive close,
every rule a change provokes — falls by roughly **40–55%**, on almost every case, on
every runtime. A window drag, which is close to pure arithmetic over geometry, falls
**80–95%**. The flagship calendar ships at
<!--stat:calendar.wireKB-->112<!--/stat--> KB gzipped, kernel included — about 20 KB more
than before, a cost paid once and deliberately, in exchange for it. The full account —
what was measured, on what basis, and which ideas were tried and found not to
pay — is `docs/system-design/optimization-arc.md`.

## An island's boundary says its own direction

What crosses into or out of an embedded program used to be one modifier,
`external`, declared on both sides and paired by name — the direction had to be
inferred from context. It is gone, along with `App.env`. In its place, each name says
which way it goes:

```declare-fragment
player: AppIsland [ program = "player",
    provides = ["volume"],
    volume: number = { app.masterVolume },             // offered DOWN: the tenant follows it
    ],
scrubber: View [ x = { app.player.exposed("pos", 0) * trackWidth } ]  // reads what it exposes
```

A host lists what it offers **down** to a tenant in `provides`, and the tenant reads one
with `hostProvided(name, default)`. A tenant lists what it offers **up** in its App's
`exposes`, and the host reads one with the island's `exposed(name, default)`. Each value
has exactly one owner: neither side can write what the other one gives. `post`/`onPost`
are unchanged — verbs, for commands and occurrences, never continuous state.

## Padding is an inset, not a radius

`View.padding` used to share its type with `cornerRadius` — same literal shape (one
number, or four), but a radius counts its four from the top-left corner and an inset
from the top edge, and the shared name told a reader the wrong story. `padding` is now
its own type, `Inset`, with its own page in the reference.

## Also in this release

A rendering defect from earlier in this arc's development is fixed: a container that
painted while its content was still empty could keep a stale record of its own bounds,
and a child added afterward would never appear until something forced a full repaint —
visible only on a narrow, phone-sized canvas, which is why it shipped unnoticed. The
Mac host now reports a failed program load to whatever is driving it, not only to the
screen.
