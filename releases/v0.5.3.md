# touch that holds up on a phone, fields judged however they are filled, and names that mean what their own scope says

Pages that swipe, switches that slide, and a bar that stays at the bottom of a phone's screen
through its bounce and its chrome: touch was worked through on a real iPhone and the
simulator, and each thing that felt wrong was fixed or written down. Any text field can now
be judged by its `validate`, bound or not. And the compiler no longer confuses a name with
the same name somewhere else in the program or the library.

## Pages that follow the finger

`Carousel` lays its children side by side, one in view. A finger drags the row and it follows
one to one; on release it settles on a page on a spring, the next one when the drag passed a
third of the width or was a quick flick. A vertical drag on it still scrolls the page, and a
press that never travels reaches the page's own controls. Assigning `page` springs it there.

```declare-fragment
Carousel [ width = 100%, height = 160,
    View [ fill = #F6D7C3, Text [ x = center, y = center, text = "One" ] ],
    View [ fill = #CFE5D2, Text [ x = center, y = center, text = "Two" ] ] ]
```

A `Switch`'s thumb can be slid across as well as tapped. A view with `onPinch` keeps the page
from panning under a two-finger pinch.

## A bar at the bottom of a phone

A pinned bar that sits at the App's bottom edge is held there by the browser, so it stays put
through the page's bounce and the browser's toolbar coming and going, with no script moving
it. With `edges = cover` it runs through the home-indicator band, and nothing is declared for
the band:

```declare-fragment
App [ edges = cover,
    bar: View [ ignoreScroll = true, y = end, width = 100%, height = 64, Button [ label = "Pay" ] ] ]
```

`ignoreScroll` pins a direct child of a scroller or of the App; deeper, a view moves with its
parent, and the boot check says so. A quick tap shows its pressed look long enough to see.
After a tap that changed what is under the finger, the mouse events the browser sends for it
are dropped, so the next screen's field does not take them.

## Any field can be judged

`validate` judges a field's text whenever it changes — typed, or written by the program — and
`error`, `valid`, `judgeOn` and `judge()` follow, as they do for a `<->`-bound field; a screen
reader hears `error` with the field. A bound field also commits and keeps `dirty`.

```declare-fragment
TextInput [ purpose = cardNumber, text = { app.group(app.digits) },
    onInput(t: string) { app.digits = t.replace(/\D/g, "") },
    validate(v: string) -> string { return v.replace(/\D/g, "").length == 16 ? "" : "16 digits" } ]
```

Inside `onInput`, `selectionStart` is the caret after the keystroke, and a `select()` made
there lands once the field shows the text the handler wrote — so a field that regroups as it
is typed can put the caret back where the person was. A `Combobox` takes a `purpose`
(`country`) and hands it to its field, and text that arrives whole and names one item, as
autofill's does, picks that item.

## A name means what its own scope says

A name used in one class no longer changes what the compiler concludes about the same name in
another. The cases this fixes: a path through a member named like a library formula
(`app.card.active.text`) is wired whole, so its value no longer goes stale; a data field
called `members` or `children` is data; a method named after an event is counted as called;
a nested dataset is checked against its own schema; a class member written beside a script
`let` of the same name is the member; a script `type Column` is the script's own; a start
call counts only for its own Animator; `link` is navigation only on a view. Where a receiver
cannot be known ahead of time, its reads are tracked as the program runs.

## Smaller changes

- `direction = rtl` (or `ltr`, `auto`) sets a subtree's writing direction; a `Text` with no
  `textAlign` of its own starts at the right.
- New warnings: `rowIndex` read on a view that is not replicated (DECLARE4023), and a write to
  a dataset that computes its value with `contents` (DECLARE4024).
- `declare-help <Preset>` prints the preset's token values.
- `declare-look --semantics` prints the whole tree.
- Assert scripts: a press waits for its target to hold still, and passes over views that take
  no presses; keys take chords (`Meta+a`); `drive.selectAll(path)`; `expect.text` reads a
  view's visible descendants; `drive.wait` lets a native smooth scroll finish.
- The docs rail's titles fit their column, ending in an ellipsis when one does not.
- The FAQ says how to install Declare as a dependency; the getting-started page is shorter.
- The Venue checkout run 3 report is filed.
