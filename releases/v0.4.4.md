# text treatments, and styles by name

Text grows a full paint vocabulary, and named styles become one idea a view and
a run of prose both speak — the same look defined once and worn anywhere.

## Treatments on any run

A `Text` used to be colour, size, weight, italic. The decorative surface is now
first-class on any run — and on every span of rich text:

```declare-fragment
Text [ textColor = white, fontWeight = bold, outline = outline(1, #C0392B), text = "OUTLINED" ]
```

- `outline(width, color)` strokes the glyph **edges** — outlined type, not a box
  around the run; the stroke rides under the fill, so a filled letter shows a ring
  and an unfilled one reads hollow.
- `textTransform` — `uppercase`, `lowercase`, `capitalize` — reshapes the glyphs
  **without changing the string**, so selection and find-in-page still see what you
  wrote.
- `smallCaps` sets the lowercase as small capitals, synthesized from the current font.
- `underline` and `strike` rule the run.
- alongside the existing `textFill` (a gradient clipped to the glyphs) and `textShadow`.

They measure and render identically on all three renderers — DOM, canvas, and the
native Mac host — so `?render=canvas` and the desktop app draw the same treated text.
`smallCaps` and `uppercase` are measured at their *true* width, so a transformed run
still wraps and aligns correctly rather than overflowing.

## Styles by name

A treatment lives on the run, which raises the obvious question: how do you avoid
repeating a look? Declare it once as a top-level `style` bundle, and refer to it by
name.

```declare-fragment
style kw   [ textColor = #C678DD ]
style hero [ fontSize = 40, textFill = { gradient("90deg", 0x4C8DFF, 0x37E0C8) } ]
```

The same bundle is worn two ways. A `Text` wears it by list — `Text [ styles = [hero] ]` —
and a `<span class>` names it in `HTMLText`/`Markdown`: `<span class='kw'>class</span>`.
One definition colours both a live code panel and a documentation snippet; a wordmark is
a gradient in the header and inline in a sentence, from one line. A bundle's *prevailing*
slots set on a container cascade to its `Text` the way a theme does, and a bundle field
may be a `{ }` body that re-derives — so a themed style follows dark mode with no extra
wiring. (`HTMLText`'s old fill-only `accents` folds into `textStyles`; a fill is now just
one of the treatments.)
