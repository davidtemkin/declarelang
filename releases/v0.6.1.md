# moving a program finds its own classes too, and breaking changes come first

`npx declare-changes` now finds the places your own classes need a change, not only the
library's, and 0.6.0's list has the two changes the first real program to move needed and
didn't have. If you moved a program to 0.6.0 already, run it again. Release notes now put what
breaks first. This release breaks nothing.

## New

### `declare-changes` follows your own classes

A program written against an earlier release often wraps the library's controls in classes of
its own: an `InputBox` that extends `TextInput`, a `Check` that extends `Checkbox`. A change to
`TextInput` applies to every one of them, and `declare-changes` now finds them there. A change's
`Find:` can name a class in braces, `{TextInput}`: that class, or any class extending it, the
library's or the program's own.

Two changes are added to 0.6.0's list:

- **A control's value from your state → `<->`, or a `commit` beside it.** A value control changes
  its own value, so `checked = { app.muted }` alone is refused. Write `checked <-> app.muted`;
  or, where the change goes through an action of yours, keep the constraint and add
  `commit(v)`.
- **`value`, `editing` or `shown` declared by your own class.** Every value control has them
  now. A class that kept its own draft and saved it when the person left is what
  `commitOn = "end"` does: delete the draft and use the control's.

### Release notes put breaking changes first

Every release's notes now have one order: an introduction, then `## Breaking changes` when
there are any, then `## New`, then `## Smaller changes`. The Release page counts the breaking
changes before they begin. A release without the section breaks nothing; a release with it
takes the next minor version. 0.6.0's notes are rearranged this way.

## Smaller changes

- `declare-help` answers the concepts of the edit model again (`validation`, `required`,
  `disabled field`, `commit on blur` and others): they pointed at `TextInput`, and now point at
  `ValueControl` and `Control`, where those members live.
- `declare-help padding` and the other CSS-instinct names keep their CSS orientation however
  long the entry above it is.
- A production build whose `.declare` sources sit in the app's own folder answers `?segments`
  for them again.
- Guide chapter 19's `Switch` example uses `checked <-> app.wifi`.
