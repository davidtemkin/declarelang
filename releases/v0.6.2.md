# forms and focus that do what they say

Fields, the combobox and the keyboard now behave as their documentation says, in the places
where they didn't. Misspelled data paths in handlers are caught at compile time. Every value
control inside a `Field` is named by it, and text fields are a finger's size on phones. This
release breaks nothing; a program that compiled before may now be told about a mistake it
already had.

## New

### A misspelled `:path` is caught wherever it is written

A `:path` is checked against the record's schema, so `:titel` on a record whose fields are
`title, left` is refused at compile time with the fields named. That check now reaches every
place a path is written: an attribute's `{ }` code, and a method's or handler's body, for a
read and for a write alike.

```declare-fragment
schema Show [ title: string, left: number ]
```

```declare-fragment
Text [ datapath = :list[], text = { :title ?? "" },
    onClick(e: PointerEvent) { :left = :left - 1 } ]
```

Written `:lefft` in that handler, it was a read and a write of nothing; now it is
`':lefft' — 'lefft' is not in the schema here; fields: title, left`.

### A `Field` names whatever value control it holds

A `Field`'s caption is the accessible name of the control inside it, for every value control:
a `TextInput`, a `Stepper`, a `RadioGroup`, a `Combobox`, or one of your own. A `Stepper` or a
`RadioGroup` in a `Field` had no name at all. A control that sets its own `accessibilityLabel`
keeps it.

```declare-fragment
Field [ label = "Seats", Stepper [ value = 2, min = 1, max = 9 ] ]
```

### Text fields are a finger's size on a touch screen

On a touch-first device a one-line `TextInput` is 44 points tall, as every other control
already is there: its top and bottom insets grow past the theme's `fieldPadding` until it is.
A field whose `padding` or `height` you set is left as you set it. On the desktop nothing
changes.

### A combobox's list is suggestions beside a field

The list a `Combobox` opens now behaves as a combobox's does everywhere, not as a menu:

- a press elsewhere closes it and goes on to what was pressed (a menu still swallows that
  press);
- Tab with the list open closes it and moves to the next stop;
- focus moved on to another view, from code or by a person, closes it and settles what was
  typed, as leaving the field does;
- text that arrives while nobody is in the field, from autofill, is settled the same way:
  it picks the one item it names, or clears a choice it no longer says, and opens no list.

### A bare name reaches a child that has `exists`

In a method, a named child is reached by its bare name, and that now includes a child with
`exists` and one inside a `State`. It is typed as possibly absent, as `this.name` is:

```declare-fragment
App [ on: boolean = true,
    hide() { if (gated != null) gated.visible = false },
    gated: View [ exists = { app.on }, width = 10, height = 10 ] ]
```

### Tab from a view that is not a stop follows your `tabOrder()`

Focus can rest on a view that is not a Tab stop: a `focusable = quiet` heading the program
focused, or a control disabled while it had focus. Tab now goes on from where your
`tabOrder()` puts that view, and from its place in the tree only when no `tabOrder()` lists
it.

## Smaller changes

- **Scrolling follows the browser.** The model's offset is always the one the browser took.
  A request the page has no room for no longer leaves the model holding it, which put every
  press that far off. A `scrollTo` made in `onInit`, before the view is on screen, now reaches
  the pane, and keeps both axes.
- A view that isn't replicated, on `datapath = :rows[0]` or `{ app.latest }`, points at a
  place: after an insert or a removal ahead of it, it shows the record now there. It went on
  showing the one that had moved away.
- A view discarded by its own handler, before that handler asks for an `afterSettle` or
  `afterDelay` step, gets no step. A form that left the screen inside its own refusal threw.
- A drawing with one mark the canvas can't take (a NaN, a negative radius, ink too far out)
  loses that mark, never the whole drawing, and the warning names the view.
- `textStyles` takes a `Font`. A class child named like a method of its base class is refused
  at compile time; it used to fail when the class was first built. `Toast.say(message)` takes
  its action as optional.
- Themes: `segmentedSelectedTextColor`, the text colour of a selected segment beside its fill.
- `declare-verify`: role and label lookups are fast on big screens, which made long scripts up
  to three times faster. A failed lookup names the script line that made it. A page error
  thrown in the library names the class and method. Collapsed warnings name their other sites.
  NaN geometry is a boot finding. A disabled control is not a target too small for a finger.
- `npx declare-changes` runs under npx, and a diagnostic merged across files names the other
  file's site.
- Docs: the platform makes what the browser's own features need (a screen reader's tree, the
  fields autofill fills) from what a program declares, and those elements are not an
  interface. `claim` narrows `onWheel` as it narrows a drag. Updating Declare is one install
  command.
