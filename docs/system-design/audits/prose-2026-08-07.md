## 11. CONFIRMED reference-tier defect — 21 library event entries are unreachable through the documented front door

**Path:** `docs/declare-model.json` (`reference`) via `tools/internal/doc/extract.mjs`
**Tier:** reference / generated model · **Class:** cross-doc · **Direction: fix-code (the generator or the help tool)** · **Verdict: CONFIRMED**

The model carries **two naming conventions for one concept**. Runtime built-ins key events by the event name (`View.event.click`); library components key them by the *handler* name (`Button.event.onClick`, `Slider.event.onPointerMove`, `Table.event.onKeyDown`, … 21 entries).

`SKILL.md:88-99` and `docs/operational/help.md` make `declare-help` the single front door for facts, and it cannot reach the second set:

```
$ node tools/declare-help.mjs Button.onClick
View.event.click — event
  Fires when the pointer presses and releases on the same view …
```

`Button`'s own distinct prose — *"Your handler. Fires after the press is delivered, so the affordance has already run…"* — is in the model and unreachable. `declare-help Button` lists `label, primary, gap, padH, inkColor, press()` and no events at all.

**Suggested resolution:** normalize the extractor to one key form (`Class.event.<event>`, matching the code's vocabulary — the handler name is derived, per `runtime/src/schema.ts` `handlerName`), or teach the help tool to prefer the most-derived class's entry when both exist. Either way the fix is in code; the reference must match the code's one vocabulary.
