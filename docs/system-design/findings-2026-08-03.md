# Findings — the 2026-08-03 agent round

> **Provenance.** Seven agents, all Opus, each given a frozen copy of the tree and a
> live server, none aware of the others. Three profiles: an LLM answering *as itself*
> about writing the language; a senior front-end developer with an architectural bent;
> and (round 1) an adoption decider, (round 2) a design engineer.
>
> **Two briefs, and the difference matters.** Round 1 asked them to note anything
> "inaccurate, stale, or overstated, with the file and line" — an audit commission, and
> it produced an audit. Round 2 said explicitly *this is not an audit*, told them to
> follow their interest and stop when it stopped holding them, and foregrounded using
> the demos and the live editors. Round 3 was a single-variable A/B on the headline.
> The engagement-framed rounds found **more** real defects, not fewer, because they hit
> them while building rather than while looking.
>
> **Relationship to `findings-2026-07-29.md`:** that round is NOT obsolete. Its A1
> (dependency extraction drops reads through a call), A3 (theme untyped) and C11 (no
> did-you-mean on attributes) were all re-found independently here, five days later, by
> agents who had never seen it. Re-discovery by a stranger is the strongest evidence a
> register like this can carry, and it is recorded per-item below.

## How to read the Verified column

- **✓ me** — reproduced in this repo, at the terminal, by the author of this file.
- **✓ agent** — the agent showed a concrete repro; not independently re-run here.
- **claim** — asserted, plausible, not yet checked.
- **✗ false** — checked and the agent was wrong. Recorded so nobody re-chases it.

## E. The one structural finding: accessibility

Every profile reached it independently, from different directions, in both rounds — and it is the only item any of them called *blocking*.

Measured: **0 `role`, 0 `aria-label`, 0 landmarks, no `<html lang>`** across all three demos; the tracker is 2,887 divs + 1,093 spans with 0 headings; the only ARIA emitted anywhere in the runtime is `aria-rowcount`/`aria-rowindex` on virtualized lists. Cause: every view is a hardcoded `div` (`runtime/src/dom-backend.ts:515`), there is no `role`/`aria`/`alt`/`tag` attribute to author, and `runtime/src/keys.ts:194-197` `preventDefault`s Tab while never setting `tabindex`.

**The important correction, which two agents made against themselves:** keyboard navigation *does* work. Declare implements its own focus model deliberately — the input notes call `tabindex` "the DOM accessibility footgun" — with `focusable`, `focusTrap`, `tabOrder()`, `FocusRing` and per-control `focusShape()` as first-class features, and text fields are real native `<input>`/`<textarea>`. So **sighted keyboard users are served, and served thoughtfully. Screen-reader users are not served at all.** That is a much narrower and more tractable gap than "no accessibility," and the site should say the narrow version rather than the vague one.

The designed path already exists (`seo-and-semantics.md`, marked **"Status: DRAFT… Not settled"**): semantics ride *components* — a `Button` the backend realizes as `<button>` — which is coherent with the no-substrate-in-source principle. Designed and unbuilt.

## G. Recommended sequencing

**1 — Diagnostics (a day, disproportionate return).** B1, B2, B3, B5, B4. These are the surface the project sells hardest and the one every agent praised *and* found holes in. B1 alone converts the most common authoring failure from a dead end into a named fix, and the machinery already exists.

**2 — The three silent-value bugs (A1, A2, A3).** Not because they are frequent, but because each one falsifies the central claim in the place the claim is loudest. A1 is likely the cheap half of a known-expensive problem: `dep-extract.ts:675` documents the *parameter* door and says closing it "refuses live code in three shipped apps" — but A1 is the *return-value* door, where the extractor already computed the right root and merely dropped the caller's tail. Worth establishing whether it separates. A2 needs a test more than a fix — a documented core form with no coverage is how it survived.

**3 — Prose corrections (C1, C2, C3, C5, C6).** Cheap, and they are what a careful reader trips on. C5 and C6 are the two where the page currently says something untrue; those first.

**4 — Accessibility (§E).** The only blocking item, the only structural one, already designed. Everything above is smaller than this and none of it substitutes for it.

**5 — Enhancements (D3, D4, D5).** D3 and D4 are cheap and both improve the argument rather than the product.

**Deliberately not sequenced:** D6 / A4 (theme typing) remains an open *design* question from the previous round, not a mechanical fix, and shouldn't be picked up as one.

## H. What they praised — kept because it is what to protect

- **The compiler's wrong-language hint table.** Every profile singled it out. *"They have a named error category called 'the CSS instinct'"* — sourced from observed eval failures rather than imagination, with a sibling table naming the rewrite for each retired spelling. One agent: *"that idea is correct and it is going to get copied."*
- **The last good render survives a failed edit.** Repeatedly called better than any hot-reload setup they use.
- **`explain()`** — the thing that localized both silent-value bugs. *"I have never once been able to ask React what this memo is actually subscribed to."*
- **`docs/declare.md`, and specifically "Six differences, stated against what you already know."** Two agents wrote a working app from that file alone. One called it the best LLM-targeted language spec it had read and said it would steal the *form* regardless of the language.
- **The calendar as argument rather than demo** — four views as one continuously-parameterised rectangle. Every agent that read the source changed its assessment at that moment.
- **The verification ladder**, and that it has a written section titled "What a rung cannot see."
